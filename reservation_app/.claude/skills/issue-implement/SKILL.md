# Issue実装(reservation_app)

設計書に沿ってコードを書く工程。実装は理解を伴う作業なのでサブエージェントに丸投げせず、この会話のメインセッションが直接行う。共通規約は `issue-flow` スキルを参照。

## 前提

`docs/issues/<番号>/design.md` が存在し、ユーザーの承認が得られていること。なければ先に `issue-design` を実行する(ユーザーに確認)。

## 手順

1. `git status` で未コミットの変更がないか確認する。あればユーザーに確認してから進める(勝手にstash/破棄しない)。
2. ベースブランチ(通常 `main`)を最新化するかユーザーに確認し、`git checkout -b issue-<番号>-<スラッグ>` でブランチを作成する。
3. `docs/issues/<番号>/design.md` の「実装ステップ」に沿って実装する。各ステップで:
   - 既存コードの命名・構成規約に合わせる(design.mdで洗い出した参考実装があればそれに倣う)。
   - タスクに不要な範囲のリファクタ・抽象化・コメントは追加しない(このプロジェクトの既定方針)。
4. 意味のある単位でコミットする。コミットメッセージに `#<番号>` を含める。
5. 実装が一通り終わったら、design.mdの「実装ステップ」全てに対応するコミットがあるか確認する。
6. ラベルを `stage:ready-for-dev` → `stage:in-progress` に付け替えてよいかユーザーに確認してから実行する(実装開始時)。実装が完了したら `stage:review` への付け替えも確認する。
7. **リモートへのpushはここでは行わない。** push/PR作成は `issue-flow` の最終ステップ、またはユーザーの明示的な指示があったときのみ行う。

## 完了条件

- design.mdの実装ステップに対応する変更がコミットされている
- `git status` がクリーン(意図しない変更が残っていない)
- 次の `issue-review` に進める状態になっている
