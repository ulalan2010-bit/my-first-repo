# 12. 非機能要件

## 要件一覧

| ID | 要件 |
|---|---|
| NFR-001 | 患者向け画面は日英併記 |
| NFR-010 | 職員画面は認証保護 |
| NFR-011 | 非提示オプション利用者のPII非保存 |
| NFR-012 | PII期限後の自動パージ |
| NFR-020 | 枠はデフォルト非公開 |
| NFR-030 | アレルギー・禁忌・異常値の視覚強調 |
| NFR-031 | ヘッダー編集・SOAPに監査証跡 |
| NFR-040 | 診断書・紹介状・検査サマリー等の生成にAIを利用する場合、患者情報を外部の一般公開AIサービスへ送信せず、セキュリティが担保された閉域環境のAIを利用する |

## 対応環境（参考）

| 項目 | 要件 |
|---|---|
| 対応端末 | Windows、Mac、iPad、Androidタブレット、スマートフォン。主利用はPCまたはタブレットを想定。 |
| 対応ブラウザ | Google Chrome、Microsoft Edge、Safariの最新版系統。 |
| レスポンシブ | 小画面では患者ヘッダーを折り畳めるが、ID・氏名・性別・重要アレルギーは常時確認できる。 |
| 性能目標 | 患者検索・カルテ本文は3秒以内、テキスト保存は2秒以内、画像一覧は5秒以内。 |
| 日時 | 日本標準時を基本とし、データベースにタイムゾーン情報を保持する。 |

## セキュリティ・バックアップ（将来の本番運用時の目安）

- 通信はすべてHTTPSで暗号化。患者基本情報、診療記録、PII、画像・動画・PDF、バックアップを暗号化して保存し、暗号鍵はデータ本体と分離管理する。
- 個別アカウント発行（共用禁止）、十分な強度のパスワード、多要素認証、一定時間操作なしで自動ログアウト、退職者アカウントの速やかな停止。
- 定期自動バックアップ（暗号化）、本番環境と別の場所に保管、変更・削除から保護、定期的な復元テスト、目標復旧時間・許容データ損失時間を運用開始前に定める。

現時点のプロトタイプでは職員パスコードのみで保護しており、上記は本番化に向けた非機能要件の目安として記載する（[今後の検討事項](13_今後の検討事項.md)も参照）。
